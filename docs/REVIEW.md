# Review

An honest review of this repository as it stands: what it does well, where
it is weak, and how much each weakness matters. Every finding points to a
file and line. Severity: **High** means the design breaks under ordinary
production failures; **Medium** means it costs money, throughput or
operator time under load; **Low** means a sharp edge with limited impact.
Fixes refer to [IMPROVEMENTS.md](IMPROVEMENTS.md) by item number.

## Known limitations

These are deliberate simplifications of a reference project.

- **Fakes stand in for third parties.** `fakerisk` is the screening
  provider and the webhook receiver lives in the notifications process.
  Their deduplication is in memory and dies with the process.
- **One of everything locally.** One PostgreSQL server for three
  databases (with a role each), a single-node Redpanda, so `acks=all` means
  one broker, and Prometheus without Alertmanager.
- **The images** pin base images by tag, not by digest, and the Dockerfile
  uses no BuildKit cache mounts: a source change downloads the modules
  again.
- **Accounts come from a seed file.** `OpenAccount` exists in the gRPC API
  but not in the REST API: opening accounts is not a client feature here.
- **Amounts in one currency per transfer.** There is no conversion; a
  transfer between accounts in different currencies is refused by the
  ledger.
